# План разработки «Маршрутизатор 3.0»

> Документ Этапа 3. Цель, проблема, решение, MVP, этапы, будущие функции,
> критерии готовности. Этапы 4–9 разбиты на задачи с критериями приёмки и
> проверкой (механика `planning-and-task-breakdown`).

## 1. Цель

Автоматически формировать оптимальный месячный маршрутный лист сотрудника из
Excel-базы планирования: «Загрузи базу — получи маршрутный лист».

## 2. Проблема

Ручное распределение сотен торговых точек по рабочим дням с учётом цикличности
и географии долго и приводит к нелогичным маршрутам (скачки «север → юг →
центр»). Excel — лишь вход и выход; ценность — корректный алгоритм.

## 3. Решение

Конвейер: валидация → парсинг → нормализация → геокодирование → кластеризация →
оптимизация (два этапа) → проверка → заполнение шаблона → скачивание.
Детали — `architecture.md`, `specification.md`, `algorithm.md`.

## 4. MVP (раздел 36 ТЗ)

Загрузка базы и шаблона, проверка Excel, чтение данных, цикличность, рабочие
дни, формирование визитов, геогруппировка, распределение по дням, порядок
внутри дня, автопроверка, заполнение Excel, скачивание.

**Вне MVP:** регистрация, кабинеты, платежи, CRM, аналитика, мобильное
приложение, соцфункции, админка.

## 8. Риски и митигация

| Риск | Влияние | Митигация |
|---|---|---|
| Нет координат/геокодера | геооптимизация деградирует | fallback-кластеризация по адресу (R1), интерфейс `Geocoder` |
| `min/max` несовместимы с цикличностью | конфликт приоритетов | цикличность приоритетнее, ограничения смягчаются (R3) |
| Цикличность > рабочих дней | часть визитов не помещается | «сколько влезает» + предупреждение (R5) |
| Дубликаты Единый код | потеря точек | валидация V6 |
| OR-Tools/геокодер — тяжёлая зависимость | усложнение деплоя | отложено за интерфейсами |
