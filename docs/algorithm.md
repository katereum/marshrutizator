# Алгоритм оптимизации «Маршрутизатор 3.0»

> Самый важный документ (раздел 31 ТЗ). Описывает два этапа оптимизации
> (Stage A — распределение по дням, Stage B — порядок внутри дня), функцию
> оценки, сложность и крайние случаи.

## 0. Постановка

Дано: множество точек `P`, у каждой `frequency f(p)`; множество рабочих дней
`D` (календарь); целевая нагрузка `T = Σ f(p) / |D|`; ограничения
`min_per_day` / `max_per_day`.

Нужно: назначить каждому визиту день и порядок внутри дня так, чтобы
соблюдались приоритеты (корректность → география → цикличность → баланс →
порядок).

Алгоритм выполняется независимо для каждого сотрудника (разбиение по
`Код торгового представителя`, R2).

Задача распадается на две (раздел 9 ТЗ): **Stage A** (какие точки в какой день)
и **Stage B** (в каком порядке), решаемые независимо.

## 1. Подготовка (preprocessing)

1. **Размножение визитов.** Для точки с `f` создаём слоты
   `(point_id, slot_index)` для `slot_index ∈ [0, f)`. Всего визитов `V`.
2. **Кластеризация.** По координатам (DBSCAN, метрика Haversine, `eps` из
   медианы попарных расстояний/конфигурации, `min_samples=1`). Без координат —
   кластеризация по каноническому адресу (`locality | metro | street`).
   Результат: `cluster_id(p)`.
3. **Календарь.** Рабочие дни по `period` и флагу выходных; `D = [d0..d_{|D|-1}]`.

## 2. Stage A — распределение визитов по дням

Цель: каждый день получает ~`T` визитов, точки дня географически однородны,
повторные визиты точки равномерно разнесены.

### 2.1. Целевые дневные ёмкости

`cap(d) = clamp(round(T), min_per_day, max_per_day)`; суммарная ёмкость
`Σ cap(d)` должна быть ≥ `V` (иначе смягчаем `max_per_day` или сигналим
неразрешимость — см. §6).

### 2.2. Предпочтительные дни для цикличности

Для точки с `f` слот `j` получает «идеальный» день:
`ideal(j) = round(j * |D| / f)`, что даёт равномерный шаг (для `f=4`, `|D|=20`:
`0, 5, 10, 15`). Это мягкое предпочтение, а не жёсткая привязка.

### 2.3. Назначение кластеров на окна дней

1. Кластеры сортируются по убыванию «веса» (числа визитов).
2. Каждому кластеру выделяется окно дней длиной `≈ round(|D| * weight(c) / V)`,
   выровненное так, чтобы соседние по географии кластеры получали соседние
   окна (географическая компактность дня). Окна могут перекрываться.
3. Визиты кластера раскладываются внутри его окна, минимизируя отклонение от
   `cap(d)` и от `ideal(j)` для каждого слота.

Реализация — жадная с ремонтом: сортировка слотов по `ideal`, раскладка в
день с наибольшим свободным остатком внутри окна.

### 2.4. Ремонтная фаза (repair)

Итеративно устраняем нарушения:
- день превысил `max_per_day` → перенос визита в соседний день с запасом;
- день ниже `min_per_day` → подтягиваем визит из переполненного;
- слоты одной точки оказались «слипшимися» (интервал < `|D| / f` / 2) →
  раздвигаем в пределах допустимых дней.

Повторять до сходимости или лимита итераций.

## 3. Stage B — порядок внутри дня

Для каждого дня независимо решаем TSP-подобную задачу:

1. **Стартовая точка** (если задана — будущее; иначе точка-центроид или
   первая по порядку).
2. **Greedy nearest-neighbor:** от текущей точки выбираем ближайшую непосещённую
   (расстояние Haversine, либо по адресу-эвристике без координат).
3. **2-opt** локальная оптимизация: разворачиваем подмаршруты, пока снижается
   суммарная длина.
4. Результат — `ordered_visits`.

Реализация за интерфейсом `RouteSolver`, чтобы позже подставить OR-Tools.

## 4. Функция оценки маршрута (раздел 35 ТЗ)

```text
score = w1 * compactness        // географическая компактность дней
      + w2 * cyclic_spacing      // равномерность повторных визитов
      + w3 * load_balance        // равномерность нагрузки
      + w4 * route_length        // суммарное внутридневное расстояние
      + w5 * constraint_violation // штраф за нарушение ограничений (0 если ок)
```

- `compactness` — доля дней, где точки принадлежат малому числу кластеров;
- `cyclic_spacing` — среднее отклонение фактических интервалов от идеальных;
- `load_balance` — обратная дисперсия нагрузки по дням;
- веса `w*` конфигурируемы (раздел 34 ТЗ); в MVP равны, кроме
  `constraint_violation`, который доминирует.

`score` используется в ремонтной фазе Stage A для выбора лучшего варианта.

## 5. Валидация результата (раздел 23 ТЗ)

После сборки проверяем инварианты:

1. каждая точка присутствует ровно `f` раз;
2. нет лишних и нет потерянных визитов;
3. все даты внутри периода;
4. нет визитов в запрещённые дни;
5. `min_per_day ≤ load(d) ≤ max_per_day` (если ограничения жёсткие);
6. нет явно нелогичных маршрутов (эвристика: день со скачками между далёкими
   кластерами при наличии близких альтернатив).

При нарушении обязательных инвариантов — повторная оптимизация (другой сид /
другой порядок кластеров), до `N` попыток, затем `OPTIMIZATION_ERROR`.

## 6. Крайние случаи

| Случай | Поведение |
|---|---|
| `frequency > |D|` | «сколько влезает» (по одному визиту на день) + предупреждение (R5) |
| `V < min_per_day * |D|` | смягчаем `min_per_day` (мягкое, R3) |
| `V > max_per_day * |D|` | смягчаем `max_per_day` (мягкое, R3); цикличность не нарушаем |
| нет координат и нет геокодера | кластеризация по адресу (fallback, R1) |
| одна точка в дне | порядок тривиален |
| пустая база | `VALIDATION_ERROR` «База не содержит точек» |
| дубликаты `Единый код` | `VALIDATION_ERROR` (V6) |
| одна точка с `f=1` | один визит, любой рабочий день |
| `min/max` конфликтуют с цикличностью | цикличность приоритетнее; ограничения смягчаются (R3) |

## 7. Сложность

- Кластеризация: DBSCAN — `O(n log n)` с деревом индексов.
- Stage A: сортировка кластеров `O(k log k)` + раскладка `O(V log |D|)` + ремонт
  `O(iterations · V)`.
- Stage B: nearest-neighbor `O(|day|²)` + 2-opt `O(|day|²)` на день; суммарно
  `O(Σ |day|²)` — для 30 точек в дне тривиально.

Для 300 точек / 600 визитов общее время — секунды (без учёта геокодирования).

## 8. Детерминизм и тестируемость

- Все стохастические шаги используют фиксированный `seed` (воспроизводимость).
- Ядро не выполняет I/O: принимает структуры данных, возвращает `RouteResult`.
- Тесты (раздел 38): цикличность, число визитов, отсутствие потерь/дублей,
  балансировка, географическая группировка, крайние случаи из §6.
