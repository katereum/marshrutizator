## Кандидаты (по приоритету)

### Оптимизация
- [~] Полная модель «район обслуживается в N дней месяца» для частоты >1.
      Сейчас сделано через «якоря» частоты; можно довести до явных зон/ротации.
- [ ] Оптимизация по **времени**, а не только по км: брать `duration` из OSRM
      (`annotations=duration,distance`) или трафик Яндекса. Учесть пробки.
- [ ] OR-Tools как опциональный солвер Stage A/B (точный VRP) вместо жадного.
- [ ] Учёт рабочего времени и времени на точку (длительность визита).
- [ ] Виды транспорта (машина / пешком / общественный транспорт).

### Геоданные / OSRM
- [ ] Кэширование дорожной матрицы на диск (меньше запросов к провайдерам,
      повторные прогоны той же базы — мгновенно).
- [ ] Локальный OSRM для других регионов / несколько графов (расширить bbox).
- [ ] Альтернативный источник тайлов (CARTO) на случай недоступности OSM.

### UX / интерфейс
- [ ] Реальный прогресс обработки с backend (SSE/WebSocket) вместо имитации стадий.
- [ ] Перетаскивание точек между днями на карте / редактирование маршрута вручную.
- [ ] Повторная оптимизация с блокировками (закрепить часть назначений).
- [ ] Показывать порядковый номер точки в дне и километраж плеча на карте.

### Бизнес-логика
- [ ] Стартовая/конечная точка ≠ дом (разные точки выезда/возврата).
- [ ] Индивидуальные графики, праздничные дни (расширить `CalendarProvider`).
- [ ] Территории / закрепление точек за сотрудником (сейчас только `trade_rep_code`).
